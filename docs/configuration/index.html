Public contract

Configuration

The public configuration describes the table a consumer wants. The mapping layer translates it into the internal representation used by builders and data utilities.

Complete shape

new TableBuilder({
    htmlId: "table-root",
    data: [],
    columns: [],
    theme: "style1",
    classes: {},
    tableOptions: {
        commonOptions: {},
        headOptions: {},
        bodyOptions: {},
        footOptions: {}
    },
    topHeader: {},
    endPoints: {}
});

Top-level options

htmlId

ID of the DOM element that receives the rendered table.

data

An array of row objects. The current implementation can also read through configured services.

columns

Column definitions using dataKey, header, and optional presentation or summary options.

theme / classes

Choose a built-in theme such as style1 or style2, then override class names where needed.

Column definitions

{
    dataKey: "sales",
    header: "Sales volume",
    options: {
        width: "20%",
        align: "right",
        sortable: true,
        summary: "sum"
    }
}

sortable enables header sorting. Holding Shift, Ctrl, or Command while sorting requests multi-column sorting. Summary behavior is consumed by the footer builders.

Top header and search

topHeader: {
    show: true,
    label: "Customer directory",
    placeholder: "Search customers..."
}

The top header delegates search input to TableBuilder.handleSearch(), which filters the prepared data through the repository's search utility.

Public versus internal names

Consumers use readable names such as tableWidth. Internally, mapping produces names such as inTableWidth, and extraction applies defaults and normalizes size values. Application code should stay on the public side of this boundary.
